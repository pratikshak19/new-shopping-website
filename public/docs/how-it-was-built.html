Trendora is a front-end system with a simulated back end. That is enough to demonstrate routing, state, validation, persistence and UX.

2. Tools and why

  1. Vite — one-second start for the lab.
  2. React — the component tree matches store pages.
  3. React Router — a URL for every screen.
  4. Context API — one provider is the “database + session”.
  5. localStorage — cart and orders survive refresh.
  6. Plain CSS — every style can be explained in a viva.

4. Build sequence (say this in the viva)

Step 1 — Product thinking

Mapped the journey: land → browse → filter → product → bag → coupon → address → pay → track.

Step 2 — Catalogue

PRODUCTS is an array of objects. Helpers formatINR, discountOf, searchProducts keep the UI thin.

Step 3 — Global state

StoreProvider owns user, cart, wishlist, coupon, orders and toasts. Writes to trendora-store-v1.

Step 4 — Pages

Home, Shop, Product, Cart, Checkout, Orders, Wishlist, Auth, Profile, About, Contact, FAQ.

Step 5 — Visual system

Navy #1A1A2E, rose #FF3F6C, cream paper, Playfair + Outfit.

Step 6 — Polish

Announcement bar, badges, empty states, 404, mobile drawer, PIN checks, coupon errors.

Step 7 — Documents

This guide, the project report, and a keyboard-driven slide deck.

5. How to run

cd new-shopping-website
npm install
npm run dev

Then open the printed URL (usually http://localhost:5173).

npm run build
npm run preview

6. How money is calculated

subtotal    = sum(price × qty)
productSave = sum(mrp × qty) − subtotal
coupon      = 10%/20% if min met, or ₹100, or free ship
shipping    = 0 if subtotal ≥ 999 else 79
grand       = subtotal − coupon + shipping

7. Auth — honest version

Passwords live in localStorage only for the demo. A real site hashes passwords on a server and issues a session/JWT. Say this out loud if asked about security.
